## Найденные проблемы

| ID | Приоритет | Область | Статус | Наблюдаемое поведение и причина |
|---|---|---|---|---|
| UI-01 | P1 | Global Macros | подтверждено | `MainWindow._set_global_macro()` вызывает `engine.apply_macros()` на каждом `valueChanged`, а затем дополнительно планирует `engine.generate()`. При 101 движении слайдера было 101 вызов `apply_macros`. Это объясняет рывки и торможение ползунков. Нужна коалесценция: обновлять значение сразу, а маршруты и генерацию применять одним отложенным проходом. |
| LIVE-01 | P1 | Global Macros / LIVE | подтверждено | `MusicEngine._apply_global_macros()` вызывается в SEQ-генерации, но не в `live_event()`. При отсутствии активной phrase изменение `energy` и `density` не меняло live-события: последовательности velocity совпадали, число пропусков не менялось. Макросы в LIVE должны проходить через тот же этап преобразования события. |
| UI-02 | P1 | Restore project | подтверждено | После загрузки demo-модели `engine.director.phrase.phrase_id == "climax_release"`, но combo в `PhrasePanel` показывает `"opening_bloom"`. `_install_project()` синхронизирует Director, но не устанавливает combo phrase из `project.phrase_state["phrase_id"]`. В результате модель и видимый UI расходятся. |
| DRUM-01 | P1 | Drum voice / channel | подтверждено | `_set_channel()` не выставляет `midi_channel_override` для выбранного `DrumVoice`. Канал в модели меняется, но override остаётся `False`, поэтому последующая нормализация drum voices может вернуть канал к родительскому. В тесте после выбора voice и установки канала 7 модель имела `midi_channel=7`, `midi_channel_override=False`. |
| DRUM-02 | P1 | Drum voice / pinned kit | подтверждено | При выборе drum voice `selected_block_id` содержит ID родительского DRUM, а `selected_drum_voice_id` — отрицательный ID voice. `_set_channel()` и `_set_note()` проверяют только `selected_block_id`, поэтому закреплённая kit-строка не обновляется. Воспроизводимо: модель показывает канал 7, а stepper в kit остаётся на 1. |
| MIDI-01 | P1 | MIDI discovery | подтверждено | `DrumKitEditor._build()` вызывает `get_midi_output_names()` отдельно для каждой voice-строки, Inspector вызывает его ещё раз. При старте без ALSA MIDI появляется много одинаковых сообщений и лишних обращений к backend. Список портов нужно получать один раз на refresh и передавать в строки/Inspector. |
| ROLL-01 | P1 | Piano roll / DRUM | подтверждено | Transport отправляет drum-события по ID дочерних voices, но при выборе родительского DRUM `_update_piano_roll()` ищет историю по ID контейнера. Поэтому реально звучащие drum notes не отображаются в roll; запасной fallback рисует агрегированный pitch 0. Нужно агрегировать историю дочерних voices или показывать отдельную voice-полосу. |
| REL-01 | P2 | Relations | подтверждено | Встроенные связи `DRUM→BASS` и `CHORD→MELODY` всегда применяются в engine, но в Relations UI не отображаются. Явная связь той же пары не заменяет встроенную, а добавляется к ней: для `DRUM→BASS` результат с явной связью отличается и эффекты складываются. Пользователь не видит полный граф и может случайно удвоить влияние. Нужно показывать built-in routes или явно разделить/обозначить их при редактировании. |
| ROLL-02 | P2 | Piano roll / CHORD/PAD | подтверждено | `record_generated_event()` сохраняет только scalar `event["pitch"]`. CHORD и PAD несут массив `event["pitches"]`, а transport отправляет все ноты. В истории и piano roll остаётся только одна нота вместо фактического voicing. |
| DRUM-03 | P2 | Drum voice inspector | подтверждено | Изменение `algorithm` или pattern в kit regenerates родительский блок, но не всегда ставит refresh Inspector. Сейчас refresh привязан в основном к `mode`; выбранная voice может продолжать показывать старые контролы/параметры до ручного переключения. |
| MACRO-01 | P2 | Project load / routes | подтверждено анализом кода | При загрузке проекта `_install_project()` вызывает `engine.generate()`, но не `engine.apply_macros()`. `generate()` тоже не применяет маршруты через `apply_macros()`. Значения маршрутов могут быть применены только после первого ручного движения макроса; это опасно для проектов, которые загружаются с ненулевыми routes. |
| MIDI-02 | P2 | Drum port inheritance | риск по коду | Для drum voice с пустым собственным `midi_port` отправка может использовать унаследованный порт родителя, а recovery `_reopen_port()` получает исходную пустую строку voice. При ошибке порта восстановление может обратиться не к тому имени. Нужен единый resolved port перед отправкой и reopen. |
| UI-03 | P2 | Global Macros layout | подтверждено | Каждый macro slider имеет `setFixedWidth(150)`, а `global_macro_bar` не растягивается по ширине окна. На ширинах 820–1600 px панель остаётся той же ширины; при узком окне верхняя строка уплотняется, при широком остаётся пустое место. Нужна адаптивная ширина/растяжение четырёх одинаковых регуляторов. |
| UI-04 | P3 | Legacy UI code | исправлено | Неиспользуемые `PerformMacroPanel`, `BlockStatePanel` и `CollapsibleGroup` удалены после перехода на единую header macro bar и текущую Inspector accordion-модель. |
| TEST-01 | P3 | Regression coverage | подтверждено ограничением тестов | Автотесты проверяют модели и генерацию, но нет устойчивых behavioral-тестов для непрерывного drag макроса, восстановления phrase в UI, drum voice channel override, MIDI history для parent DRUM и фактической отправки на устройство. Нужен следующий слой Qt/transport behavioral tests. |

## Приоритет исправлений

1. Сначала устранить `UI-01`, `LIVE-01` и `UI-02`: они влияют на все проекты и создают впечатление, что глобальные настройки/phrase не работают.
2. Затем исправить `DRUM-01`, `DRUM-02`, `DRUM-03` и `ROLL-01`: это наиболее заметные ошибки нового drum workflow.
3. После этого привести в порядок `MIDI-01`, `MIDI-02` и `MACRO-01`, чтобы загрузка и запуск не зависели от количества voice и состояния MIDI backend.
4. Сделать relations граф полным (`REL-01`), затем добавить behavioral UI-тесты (`TEST-01`) и удалить legacy-классы (`UI-04`).
