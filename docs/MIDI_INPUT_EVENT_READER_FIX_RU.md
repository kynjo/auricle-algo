# Исправление приёма MIDI IN

## Симптом
Auricle обнаруживал MIDI-устройство и успешно открывал порт, но входящие сообщения не доходили до MIDI Learn. Внешняя проверка устройства в Surge XT подтверждала, что аппаратный контроллер и системный MIDI-драйвер работают.

## Причина и решение
Ранее входящие события принимались через callback `mido.open_input(..., callback=...)`. Поведение callback зависит от MIDI backend и способа доставки сообщений. Заменено на переносимый путь Mido: порт открывается без callback, отдельный фоновый поток опрашивает `iter_pending()` и передаёт нормализованные события в Qt через queued signal.

GUI-поток не опрашивает MIDI порт и не выполняет работу MIDI backend. События CC, Note On, Pitch Bend, Channel Aftertouch и Polyphonic Aftertouch декодируются в `midi_learn.py`. Неподдерживаемые сообщения игнорируются.

При отключении входа reader thread останавливается до закрытия порта. При загрузке другого проекта старый reader корректно отключается. В менеджере MIDI Learn отображается последнее принятое сообщение.

## Проверки
- 2 unit-теста reader loop пройдены с имитацией Mido input port.
- Python-компиляция `auricle_gui.py`, `midi_input_reader.py`, `midi_learn.py` успешна.
- Физический контроллер и Qt GUI в этой среде недоступны, поэтому аппаратный end-to-end тест не заявляется.
