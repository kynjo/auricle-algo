# Перенос редакторов на Transport Command Queue

Все изменения модели из четырёх редакторов теперь применяются транспортным потоком через `Transport.enqueue_gui_command()` на границе тика.

## Перенесённые редакторы

- **Composition Planner**: локальный draft-конфиг; commit snapshot; сброс контекста секции и генерация выполняются в транспортной команде. Отключение блока/голоса в текущей секции освобождает его активные ноты в той же транзакции.
- **Harmonic Plan**: редактирование списка аккордов идёт через локальный draft; замена `project.harmonic_plan` и reset `harmonic_runtime` выполняются в очереди.
- **Instrument Dialogue**: параметры relation собираются в GUI draft; запись `relation.parameters` и `engine.apply_relations()` выполняются в очереди.
- **Parameter Influence**: policy и последующая регенерация блока отправляются отдельными командами; быстрые изменения одной policy coalesce-ятся по ключу.

## Согласованность и отзывчивость

- Команды привязаны к идентичности проекта; устаревшая команда не применяется после замены проекта.
- UI немедленно показывает локальное draft-значение, не изменяя объект модели, который читает Transport.
- Очередь coalesce-ит быстрые правки одного параметра и сохраняет FIFO между разными операциями.
- `Parameter Influence`, `Harmonic Plan` и `Instrument Dialogue` используют неблокирующее чтение runtime-состояния; при занятом транспортном lock обновление UI пропускается до следующего refresh.
- Сохранение и Undo/Redo продолжают вызывать flush очереди до снимка документа.

## Проверки

`tests/test_editor_command_migration.py` проверяет архитектурную границу статически. `tests/test_transport_command_queue.py` проверяет FIFO, coalescing, применение при остановленном транспорте, flush, обработку ошибок и независимость от GUI lock.
