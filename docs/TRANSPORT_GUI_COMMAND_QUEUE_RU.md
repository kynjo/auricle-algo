# GUI → Transport command queue

## Цель

Убрать одновременную запись в активный граф проекта из Qt-потока и чтение этого
графа транспортным потоком. GUI передаёт изменения через
`Transport.enqueue_gui_command()`. Команды применяются транспортным потоком в
начале `Transport.tick()`, до обработки музыкальных событий.

## Гарантии очереди

- Очередь потокобезопасна и не захватывает GUI lock.
- Команды без ключа выполняются в FIFO-порядке.
- Команды с одинаковым ключом объединяются: сохраняется позиция первой команды,
  но callback и notification заменяются последними значениями.
- Команды, добавленные во время drain, остаются в очереди до следующего тика.
- Ошибка одной команды логируется и не отменяет выполнение следующих команд.
- Очередь обслуживается также в STOP: worker продолжает idle ticks.
- START и SEEK применяют накопленные изменения до смены позиции/режима.
- STOP не выполняет вложенный drain: он может вызываться изнутри `tick()` при
  завершении Composition. Оставшиеся команды применятся следующим idle tick.
- Перед сохранением, Undo/Redo, заменой проекта и завершением приложения очередь
  принудительно осушается под `_transport_lock`.

## Перенесённые операции

- Параметры Block Inspector: объединение изменений одного блока и одна регенерация.
- Global Macros, глобальные Key/Scale, Tempo и Project Length.
- MIDI Expression overrides, MIDI Sync, MIDI note/channel/port routing.
- Block mute, rename, type, algorithm, mode, add/delete.
- Drum Kit: параметры, голоса, Pattern steps, вероятности шагов, Auto Roles,
  копирование/вставка звуковых настроек.
- Mutator и Process: параметры, типы, цели, добавление/удаление.
- Relations: создание, редактирование, дублирование и удаление.
- Motif binding, step, development, hold, recall и capture.
- Perform: Phrase и Performance Card настройки, старт/стоп и обновление активных жестов.

## Потокобезопасность GUI

Команды не должны обращаться к QWidget, QTimer или иным Qt-объектам. После
успешного применения Transport отправляет простое уведомление через
`_transport_command_applied_signal`; GUI-слот обновляет dirty/history, Inspector,
карточки и статус в Qt-потоке.

Runtime UI heartbeat использует неблокирующий `_transport_lock`: если транспорт
занят, обновление пропускается до следующего heartbeat вместо ожидания.
История и сохранение используют блокирующий lock только на коротких операциях
сериализации/транзакции, предварительно осушая очередь.

## Оставшиеся legacy-пути

Не все вспомогательные редакторы переведены на очередь. В частности, часть
действий в Composition Planner, Harmonic Plan, Parameter Influence, Instrument
Dialogue и отдельных rhythm subpanels всё ещё использует старый `_state_lock`.
Этот lock не синхронизирует их с транспортным потоком. Эти редакторы требуют
отдельного переноса на command API; до этого их прямые изменения во время PLAY
остаются известным ограничением. Следующий подэтап — единый адаптер транзакций
для этих панелей и read-only runtime snapshots для сложных GUI-представлений.
