# Облегчение UI · Auricle v2.0

## Обнаруженные причины

Встроенный экспорт algo_conf наблюдал за StyleChange, FontChange, Show и
другими событиями каждого виджета. При изменении оформления он заново обходил
всё дерево Qt, отражал Python-атрибуты и искал контейнеры через тысячи временных
QLayoutItem, даже если профиль менял только размер кнопки.

В контрольном запуске без этого runtime все исходные 1865 тестов
прошли одним процессом. Это указывает на связь прежних сбоев с runtime, но не
устанавливает конкретную C++ инструкцию, повредившую heap на компьютере пользователя.

Дополнительно каждые 80 мс обновлялись скрытые средства Perform и Composition,
выбор другого Drum Voice пересоздавал закреплённый Kit, а MIDI-планировщик после
задержки выполнял серию устаревших опросов под общей блокировкой.

## Что изменено

- Сохранённые цели профиля разрешаются непосредственно по пути. Обычные
  изменения цвета, шрифта, активности или видимости не запускают полное сканирование.
  Наблюдаются только цели и их предки. Поиск layout нужен лишь явно сохранённым
  изменениям layout. Профиль размера/цвета не обходит layout items.
- Код профиля вынесен в `ui_profile_runtime.py`. Его нужно копировать вместе
  с программой. Текущий профиль сохранён. Штатный запуск выбирает этот runtime,
  даже если старый algo_conf снова запишет свой служебный блок.
- Один UI heartbeat обновляет видимые представления. В простое тяжёлые операции
  ограничены четырьмя обновлениями в секунду, при проигрывании сохраняется 80 мс.
  Кнопки транспорта по-прежнему проверяются каждые 80 мс, в том числе после
  автоматического завершения Composition.
- GUI не ждёт занятую блокировку MIDI-потока для фонового обновления. Метки
  влияний используют слабый реестр captions вместо поиска по всем виджетам.
- Выбор voice обновляет выделение и нижний Inspector, сохраняя закреплённый Kit.
  Структурные изменения — новый voice, режим, роль, длина или MIDI-настройки —
  по-прежнему перестраивают необходимую часть. Неизменённые карточки сохраняются.
- Все отложенные singleShot callbacks UI привязаны к QObject-владельцу.
  Удаление окна отменяет их. Добавлена проверка удалённого piano roll.
- Устаревшие polling ticks объединяются только в рабочем цикле планировщика.
  Очереди других callbacks не сокращаются. Transport использует актуальное
  музыкальное время, как и до исправления; штатный polling interval не изменён.
- Убраны повторное распознавание уже назначенной роли и создание набора ролей
  в горячем цикле. Сборка LIVE Drum сразу выбирает актуальный слот. В Relations
  копируются плоские числовые списки; неизменяемые числа не копируются рекурсивно,
  а компоненты без влияния не обходятся для каждого шага.

## Измерение простоя

Окно 1600×980, исходный проект с тремя блоками и 1705 виджетами; Linux,
Python 3.12.14, Qt/PySide6 6.12.0, cProfile. По три секунды работы UI:

| Показатель | До | После |
| --- | ---: | ---: |
| CPU-время процесса | 1,118 с | 0,120 с |
| Runtime профиля в верхних затратных вызовах | 0,701 с | отсутствует |
| Обновления меток влияния | 32 | 9 |

Это локальный замер простоя с профилировщиком, а не обещание одинакового
ускорения всех проектов. Смена темы и полная перестройка сложного Inspector
по-прежнему требуют работы Qt и могут занимать больше времени обычного кадра.

## Проверка

Все 1873 теста прошли одним Python-процессом (168,68 с). На минимальной Qt 6.8.3
дополнительно прошли 11 проверок UI и времени жизни объектов. В нагрузочном
сценарии за 180 секунд выполнено 420 действий и отправлено 7194 MIDI-сообщения;
ошибок Python/Qt и планировщика не было, число виджетов оставалось стабильным.
Однако максимальная операция смены темы заняла 6,64 с, а p95 интервала GUI —
1,04 с: полная плавность под нагрузкой пока не достигнута. Точная причина
исходного нативного падения на машине пользователя не установлена.

Актуальные результаты полного запуска и нагрузочного сценария находятся
в `UI_VALIDATION.json` рядом с этим документом. Общий pytest запускается одним
процессом, с faulthandler и `MALLOC_PERTURB_=165`; модули не изолируются друг от друга.
Нагрузочный сценарий использует живой TransportWorker, Composition, смешанные
SEQ/LIVE, записывающий MIDI-порт, изменения макросов, voices, режимов, темы,
Undo/Redo и перемотку. Работа на физическом MIDI-оборудовании не проверялась.
