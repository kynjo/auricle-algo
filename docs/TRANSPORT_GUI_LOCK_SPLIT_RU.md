# Разделение блокировок GUI и Transport

## Что изменено

- `Transport._state_lock` сохранён как GUI/model lock для совместимости со всеми существующими Qt-контроллерами.
- Добавлен отдельный `Transport._transport_lock` для сериализации `tick()`, `start/stop/seek`, MIDI-портов и настроек MIDI Sync.
- Декоратор `_transport_locked` больше не захватывает GUI lock.
- `set_midi_sync_config()` переведён на transport lock.
- Зафиксирован принцип lock ordering: транспортный worker не должен захватывать GUI lock; UI refresh не должен ждать transport lock.

## Эффект

Длительный транспортный тик больше не удерживает тот lock, который используется UI refresh и GUI-операциями. Команды транспорта остаются взаимно сериализованными отдельной блокировкой.

## Ограничение

Модель проекта остаётся общей для GUI и движка. Данное изменение устраняет конкуренцию за один общий mutex, но не превращает модель в immutable snapshot и не сериализует все GUI-изменения через command queue. Для полного устранения гонок следующий этап — перевод редактирования модели на очередь команд с применением на границе transport tick.
